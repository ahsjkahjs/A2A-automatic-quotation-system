ARCHITECTURE BLUEPRINT · v1.0 · CONCEPTUAL DESIGN

Agent-to-Agent
自动报价系统架构设计

基于开放的 A2A（Agent2Agent）协议，让分属不同组织的买方智能体与卖方智能体自动完成「询价 → 报价 → 比价/议价 → 授标 → 成交结算」的跨企业交易闭环；LLM 负责理解、编排与协商，确定性规则与模型掌握定价边界，关键决策保留人在回路。

01

概述与设计目标

A2A 自动报价系统把「人对人 / 门户对门户」的询价报价流程，升级为「智能体对智能体」的自动化协作：每个组织在自己的安全边界内运行 Agent，对外通过开放协议交换结构化的询价单（RFQ）与报价单（Quote），对内通过工具接口调用库存、产能、成本与定价能力。它不是让 LLM 随意报价，而是一套协议互通 + 确定性定价 + 可控自治 + 全程留痕的交易基础设施。

GOAL · 01

互操作 Interoperable

基于开放 A2A 协议与 JSON Schema 化的 RFQ / Quote，不同厂商、不同模型构建的异构 Agent 可跨组织「即插即用」，无需点对点定制对接。

GOAL · 02

自动化 Automated

LLM 完成需求理解、任务编排、多轮澄清与谈判；规则 / 定价模型完成可承诺量校验与定价，询价到报价在 SLA 内免人工，异常才升级。

GOAL · 03

可信 Trustworthy

组织与 Agent 强身份认证、最小授权、密封报价开标前不可见、可验证资质凭证、全链路不可篡改审计，防止越权报价与围标串标。

GOAL · 04

可靠 Reliable

幂等键、超时重试、报价有效期锁价、Saga 补偿与 Outbox/Inbox，保障跨组织长流程的最终一致，失败可重放、可对账。

GOAL · 05

可治理 Governable

金额阈值、自动决策边界、人在回路（HITL）权限矩阵、价格护栏与合规筛查全部策略化，自治程度可按风险动态调节。

GOAL · 06

可扩展 · 可观测

新供应商发布 Agent Card 即可被发现与接入；跨 Agent 透传 Trace，指标 / 日志 / 会话可追踪、可重放、可度量。

核心设计原则 —— LLM 不直接定价。LLM 负责非结构化信息理解、规划、多轮澄清与谈判话术、以及给出可解释说明；价格数字由确定性规则 / 定价模型在授权区间（底价、目标毛利、折扣权限）内给出。LLM 只能在该可行区间内协商，任何越界、低于成本红线或命中合规规则的请求都会被护栏拦截并升级人工，从根上杜绝「模型乱报价」。

适用 典型落地场景

B2B 原材料 / MRO / 服务采购与供应链询价、招投标与反向拍卖、物流与航运运价、云资源 / API 等服务类交易、保险报价与金融产品报价（后者须叠加行业合规与适当性适配）。共同特征：非标或半标、多供应商、需要多轮协商、交易金额值得自动化提效。

边界 不适用 / 需谨慎

大额或高风险成交不得无条件全自动，必须经 HITL；场内高度标准化合约应由交易所撮合引擎而非 A2A 议价完成；强监管品种在合规适配前不开放自动报价；A2A 面向任务级长会话，不承担毫秒级行情做市，后者需专用低延迟系统。

02

参与角色与信任边界

系统由「三方组织域 + 横切信任机构」构成：买方域、若干卖方域各自在私有边界内运行 Agent；市场运营方只做中立的发现、撮合与见证，不触碰各方成本 / 底价等商业机密；身份与审批能力横切所有域。

BUYER DOMAIN

买方智能体

需求解析与 RFQ 构建、采购策略、供应商发现与资格初筛、多属性比价、还价策略、授标建议，对接企业采购 / 财务系统。

SUPPLIER DOMAIN ×N

卖方智能体

受理 RFQ、资格预审、可承诺量（ATP）/ 产能 / 库存校验、成本核算与定价、生成并提交报价、参与多轮议价。

NEUTRAL PARTY

市场运营 / 编排方

维护注册目录与能力市场、组织询价 / 竞价会话、管理截止与开标、提供中立时钟与审计见证，不参与定价。

DISCOVERY

注册中心 Registry

托管各 Agent 的 Agent Card（端点、技能、认证方式、流式 / 推送能力）、资质凭证与信誉分，支撑能力匹配与发现。

TRUST

身份与信任机构

OIDC / OAuth2、mTLS 证书、DID 与可验证凭证（VC）签发，绑定 Agent 与所属组织，提供资质、授权与签章信任根。

HUMAN-IN-THE-LOOP

人工审批节点

买卖双方的审批人：超折扣 / 超金额报价、新供应商、异常低价、大额授标等场景，通过推送通知介入批准或否决。

SYSTEMS OF RECORD

企业后端系统

ERP / CRM / PIM 商品目录 / WMS 库存 / APS 产能 / 财务 / 汇率，经 MCP 工具网关被各自 Agent 安全调用，数据不出域。

SETTLEMENT

合同与结算

授标后生成合同 / 采购订单、CA 电子签章、履约与验收、发票、支付或资金托管（Escrow）、四方对账。

03

自上而下分为接入渠道、买方 / 卖方两套 Agent 运行时、A2A 协作协议层、交易服务层、横切的信任治理面，以及集成数据与基础设施。买方与卖方 Agent 运行时分别部署在各自组织边界内，仅经 A2A 协议层跨域通信；成本、底价、库存等敏感数据不下本地域。

04

端到端业务流程

一次自动报价交易沿四个阶段、16 个步骤推进，阶段之间设置强制「阶段门（Gate）」。常规路径由 Agent 自动流转，命中风险条件则在阶段门处升级人工或被拦截，形成「默认自动、边界可控」的自治模型。

PHASE 1
询价与发现
  • 需求结构化，生成 RFQ（规格 / 数量 / 交期 / 条款 / 评标办法 / 截止）
  • 拉取 Agent Card，按能力 / 地域 / 品类匹配供应商
  • 校验资质、授信与可验证凭证（VC）
  • 密封或公开方式 Fan-out 分发询价任务
PHASE 2
受理与报价
  • 卖方资格预审，决定是否投标
  • ATP / 产能 / 库存校验，核算可承诺交期
  • 成本拆解与定价引擎在授权区间出价
  • 护栏校验；超权限转人工，提交结构化 Quote
PHASE 3
评标与授标
  • 澄清问答与多轮还价，报价版本化留痕
  • 截止开标（密封）或实时反向竞价
  • 币种 / 税 / 贸易条款 / 交期归一化，TCO 评分
  • 输出授标建议；大额 / 异常经人审后授标
PHASE 4
成交与履约
  • 生成合同 / 采购订单（PO），CA 电子签章
  • 订单履约、发货与验收
  • 发票、支付或资金托管（Escrow）
  • 四方对账，绩效与信誉回流、价格学习
G1 资格门：资质 / 授信 / 制裁筛查不通过 → 不邀请或不予受理。
G2 定价授权门：低于成本红线或超出折扣权限 → 拦截并升级 HITL。
G3 开标门：截止前密封报价任何人不可见；到时阈值解密开标。
G4 授标门：按金额 / 异常度 / 新供应商触发人审，其余自动授标。
报价均带有效期（Validity）与幂等键：过期自动失效（流拍 / 流单），中标后在有效期内锁价转单；授标后若首选方履约失败，按预案顺延次优中标人或触发补偿流程重新询价（见第 09 节）。

长耗时的定价与审批一律异步化：调用方通过 message/stream 订阅 SSE，或先用 tasks/pushNotificationConfig/set 注册 Webhook，由卖方在报价就绪 / 待审批时主动推送，避免长连接阻塞；每次请求携带幂等键，重试不会产生重复报价或重复授标。
06

报价任务状态机

一次报价任务从草稿到结算归档的完整状态与迁移条件。竞争阶段的报价在截止前处于密封态；超权限报价进入人工审批旁支；过期、撤回、取消、失败、未中标汇入异常终态；成交后沿履约链推进，履约失败触发 Saga 补偿顺延次优中标人。

进行态 人工审批 / 密封 成交 / 履约 异常终止 补偿回流
状态持久化在 A2A Task 与交易服务库中，每次迁移都是带幂等键的事件，写入只追加的事件日志（Event Sourcing 思路），因此任意任务可断点续跑、可重放、可审计；密封态报价对买卖双方与平台均不可见，直至「截止开标」迁移触发阈值解密。
07

智能报价引擎

报价引擎是卖方 Agent 的决策核心，采用「输入 → 确定性决策流水线 → 结构化产出」。价格由规则与模型计算、由护栏约束，LLM 被限定在理解与协商层、不掌握最终定价权，从而兼顾灵活性与可控、可审计。

输入 决策依据

  • RFQ 要素：规格 / 数量阶梯 / 交期 / 交货地 / 贸易条款
  • 成本数据：BOM、原料、人工、物流、税费（经 MCP）
  • 可供给能力：库存、ATP 可承诺量、CTP 产能（经 MCP）
  • 商务上下文：客户等级、授信额度、账期、历史成交价
  • 市场信号：行情、汇率、竞争态势、需求弹性
  • 授权边界：底价、目标毛利、折扣权限矩阵

确定性定价决策流水线

  • 1 · 资格与可交付校验：是否在营品类、ATP/CTP、最小起订量、交期可行性
  • 2 · 成本核算：生成成本拆解（含税 / 到岸 / 总拥有成本）
  • 3 · 定价策略：成本加成 / 价值定价 / 竞争定价 / 动态定价，支持数量阶梯、捆绑、账期组合
  • 4 · 约束求解与护栏：底价 floor、目标毛利、权限矩阵、有效期锁价、倾销 / 管制价 / 价格歧视合规
  • 5 · 多目标权衡：在毛利 × 中标率 × 产能利用 × 风险间求可行最优
  • 6 · 审批路由：按权限矩阵决定自动发出或升级 HITL
LLM 的边界（仅协商层，不直接定价）

负责非结构化 RFQ / 图纸解析、澄清问答、谈判话术与让步节奏、生成可解释说明；只能在第 4 步给定的可行价格区间内协商。任何越界、低于成本红线或命中合规规则的请求一律拦截并转人工。

输出 结构化报价

  • Quote 主体：单价 / 阶梯价 / 总价 / 币种 / 税费 / 贸易条款 / 交期 / 有效期
  • 定价依据：成本拆解与定价理由（可解释、可审计）
  • 置信度：中标概率与价格弹性估计
  • 还价预案：让步节奏与底线（底价永不出域）
  • 审批结论：自动通过 / 转人工及原因
  • A2A Artifact：签名、版本化的报价制品
为什么不让 LLM 直接报价？价格错误是直接、可量化且难以追回的资金损失，且 LLM 输出不具确定性、易受谈判话术诱导。把定价收敛为「规则 / 优化模型求解可行域 + 护栏硬约束」，LLM 在可行域内负责语言层协商，既保留自然交互体验，又使每一笔报价都可复算、可解释、可追责。
08

信任、安全与治理

跨组织自动交易的前提是「可证明的公平、可控的自治、可追溯的责任」。信任不依赖于对某一方的善意假设，而由身份、加密、风控、权限边界与审计共同保证。

IDENTITY

强身份与最小授权

Agent Card 绑定所属组织的 DID / mTLS 证书；OAuth2 / OIDC 颁发受限 Scope；每条消息签名并带 nonce / 时间戳防重放，Agent 行为可归责到组织。

FAIRNESS

密封报价与公平开标

截止前报价以公钥加密或在 TEE 内密封，买方、卖方、平台均不可见；引入可信时间戳，到达截止时间才阈值解密 / 开标，杜绝提前泄密与暗箱改价。

ANTI-FRAUD

风控与反围标串标

检测报价雷同、关联关系、IP / 账号聚集、异常低价或陪标模式，构建供应商关联图谱；命中围标特征即冻结授标并转合规调查。

AUTONOMY BOUNDARY

自治边界与人在回路

按金额、折扣幅度、异常度、供应商新旧、条款偏离度配置权限矩阵；规则内自动执行，越界自动升级，红线动作直接禁止。

CONFIDENTIALITY

商业机密与数据最小化

成本、底价、产能、客户名单等留在各自私有域，定价在本地完成；跨域只交换经授权的 RFQ / Quote 与必要凭证，遵循数据最小化与数据主权要求。

AUDITABILITY

全链路审计与可解释

询价、报价、还价、定价依据、审批、开标、授标全部写入只追加、哈希链校验的审计日志，可重放、可举证、可接受监管核查。

09

可靠性与跨组织一致性

报价是跨企业、长耗时、可能失败的分布式事务，且涉及资金承诺。系统不追求跨组织强一致的分布式锁，而以「幂等 + 异步 + 最终一致 + 补偿 + 对账」组合保证正确性与可恢复性。

PATTERN · IDEMPOTENCY

幂等键去重

每个询价、报价、授标请求携带 Idempotency-Key，服务端持久化去重；网络抖动重试、SSE 重连不会产生重复报价或重复授标。

PATTERN · ASYNC + TIMEOUT

异步优先与超时降级

定价、审批等长操作走 SSE / Webhook 异步回传并约定 SLA；供应方不可达即熔断跳过并告知，定价服务异常回退规则价或转人工。

PATTERN · OUTBOX / INBOX

事务消息最终一致

跨组织消息先写本地 Outbox 再投递，接收方 Inbox 去重确认；「至少一次投递 + 幂等消费」实现跨域最终一致，不依赖双方同时在线。

PATTERN · SAGA

补偿而非长事务

授标后首选方履约失败，按预案顺延次优中标人或重新询价；订单到履约每一步都定义对应补偿动作，失败可回退到一致状态。

PATTERN · PRICE LOCK

有效期与锁价

报价带有效期，过期自动流拍 / 流单；中标后在有效期内锁价并预留库存 / 汇率，后续市场价波动不影响已确认订单。

PATTERN · RECONCILE

对账与可重放

报价—订单—发票—付款四方定时对账，差异自动告警；事件日志支持任意任务断点续跑与全程重放，用于纠错与纠纷举证。

分阶段落地路线

建议沿「先打通、再比价、后自治、终可信」的顺序增量交付，每个里程碑都以可运行、可验证的闭环收尾，自治程度随信任与数据积累逐步放开。

M1 · 0–2 月

点对点打通

单买方—单卖方 A2A 询价 / 报价；结构化 RFQ / Quote；规则定价；全量人工审；MCP 打通库存查询。

M2 · 2–4 月

多供应商比价

Fan-out 询价、多属性 TCO 评分、版本化议价；接入 ERP / 财务；幂等键与 Outbox 落地。

M3 · 4–6 月

自治与竞价

Registry 自助发现、动态定价、HITL 权限矩阵、反向拍卖；完整审计日志与指标看板。

M4 · 6–9 月

可信闭环

密封投标 / TEE 开标、风控反围标、合同—订单—结算闭环、四方对账与 Saga 补偿。

M5 · 9–12 月

规模与联邦

跨行业 / 多市场联邦、供应商信誉体系、价格学习优化、SLA 与容灾、规模化推广。

关键风险与对策

围绕「资金安全、公平竞争、越权自治、跨域可靠、合规追责」五类核心风险给出内建对策，相关控制点已在架构与状态机中落地，而非事后补丁。

跨组织消息丢失 / 重复 / 乱序重复报价、错单漏单幂等键去重、Outbox / Inbox 事务消息、状态机约束迁移、定时四方对账与任务重放。

14

协议分工与数据契约

A2A 与 MCP 在系统中正交分工；跨组织交换的 RFQ / Quote 以严格 Schema 定义为结构化制品（Artifact / Data Part），这是互操作与可校验的基础。

跨组织 A2A：Agent ↔ Agent

负责能力发现（Agent Card）、任务生命周期（Task：submitted / working / input-required / completed / failed / canceled）、消息与制品（Message、Text / File / Data Part、Artifact）、SSE 流式与推送。询价单、报价单、授标通知等业务事务都作为 Artifact / Data Part 在 Task 上下文中传递。

组织内 MCP：Agent ↔ 工具 / 数据

以 Resources / Tools / Prompts 统一连接 ERP、CRM、PIM、WMS、APS、财务与定价库，在鉴权、限流、审计前提下完成数据读写与函数调用。MCP 调用发生在各组织私有域内，不跨组织暴露，从而保护商业机密。
